# agent-office: design contract

An original terminal "office" for AI coding agents (Claude Code sessions plus subagents, and agy calls via `~/.claude/bin/agy-route`). It shows who is working, what they are doing, cost and RAM, raises alerts, and lets you act (approve/deny, cancel, resume).

## Crates
- `office-core`: the contract. `model.rs` (Agent, Scene, Alert, RouterStatus), `event.rs` (Event/EventKind), `reducer.rs` (fold events into a Scene; stale sweep), `alerts.rs` (loop/stuck/cost detectors), `config.rs` (TOML config), `paths.rs`.
- `office-hook`: a tiny binary that agents call per hook event. It reads stdin JSON, tags `OFFICE_SOURCE` (claude|antigravity), and writes ONE line `{"source":..,"payload":<raw>,"ts":..}` to `paths::hook_socket()`. It ALWAYS exits 0 within 300 ms. Non-permission observer hooks (including `antigravity`) exit 0 silently with empty stdout (never printing `{}` because Antigravity `PreToolUse` fails closed without `decision`, while `{"decision":"allow"}` would bypass prompts); with `--permission` it may wait (up to `permission_timeout_s`) for a decision from the TUI (see Control).
- `office`: the TUI binary (`office`). Subcommands: `office` (run), `office demo` (synthetic agents), `office install-hooks [--claude] [--antigravity] [--uninstall]`, `office doctor`.

## Sources (crates/office/src/sources/)
- `hook_socket.rs`: bounded 4-worker unix listener with `SocketGuard` cleanup; decodes Claude hook payloads (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Notification, Stop, StopFailure, SubagentStart/SubagentStop, SessionEnd, PermissionRequest) and Antigravity hook payloads (`PreInvocation` with `conversationId`/`workspacePaths`/`lastUserInput`/`modelName`, `PostInvocation`, `BeforeTool`/`AfterTool`, and `Stop` -> Boss Inbox `Result` + `Usage` via `transcriptPath`) into Events. Claude subagents: hook payloads carry `agent_id`/`agent_type` when fired inside a subagent. Map them to `cc-sub:<session>/<agent_id>` with parent `cc:<session>` and role=agent_type.
- `claude_transcripts.rs`: tails ~/.claude/projects/**/*.jsonl (only files modified in the last 2h; first-sight gate) for usage (fresh input, output, cache-read and cache-write tokens, kept separately), giving Usage events with estimated cost (a model price table in config) and context % (including 1M-context models).
- `agy_router.rs`: every 1 s, scans `ps` (with idle backoff when quiet) for `bun … agy-route --role <r> … --cwd <c>` (skipping `--dry-run` / `--status`), sums each router's descendant RSS, tracks orphan `agy` processes (`ppid == 1` outside live router trees as `ag-orphan:<pid>`, emitting `Gone` when exited), and reads `~/.claude/run/agy-route.slot*.lock` and `agy-route.worker-*.lock`. It emits AgentSeen(kind=Agy, id="agy:<router pid>", role, model from the role→model map in config, slot, pid, label "<role>·<model short>"), Resources, and Gone when the pid disappears. Every 5 s it runs `agy-route --status` and parses CAPACITY/FREE_MB/PER_PROC_MB/PRESSURE/SLOTS/QUEUE/LIMIT/MAX_CONCURRENT into a Router event (`QUEUE: <n> waiting` feeds `RouterStatus.queued`). It tails `~/.claude/run/agy-route.log.jsonl` for finished calls: errorCode TOOL_DENIED/TIMEOUT/EMPTY_RESPONSE/BUSY become Alert events, and standalone `agy-route` calls seed Boss Inbox `Result` reports (with full saved response text). The agy model per role is in the router's audit lines (`role`, `model`).

## Rendering (crates/office/src/render/)
- The scene is composed into an RGBA framebuffer (`image` crate) from a Theme: floor/wall tiles, desks with computers, decor (whiteboard with live Kanban pins, coffee bar with animated steam, server rack with router-status LEDs, lobby waiting bench), ambient ground shadows, per-tool monitor glows, and characters. Displayed in Ghostty via native compressed RGB24+zlib Kitty Unicode placeholders (`U=1`) wrapped in Synchronized Output (DEC 2026) with modal occlusion splitting (and double-buffered image IDs / exact-frame reuse), Sixel/iTerm2 via `ratatui-image` (hidden behind modals to prevent z-bleed), or direct crisp half-blocks (`▀`).
- Branding: the company name ROSSO appears in the TUI header, the back-wall plaque in the office render, and the Ghostty window title (`scripts/office-win`).
- Desk pods: light carpet tiles under each pod (no rugs), desks lit from the top-left with 1 px outlines, keyboard/mouse/mug on every desk, task chairs behind the seated agent, and a desk bench joint with a frosted privacy panel between the two seats of each row (the panel closes the vertical aisle between a pod's columns, so cat routes only use the outer aisles). Furniture other than sprites is generated procedurally from the theme's `colors` and `fx`, so every bundled theme keeps its palette.
- Layout: adaptive auto-grid of desk pods scaling cleanly to the viewport. Each top-level session gets a pod; its subagents and agy calls sit at the pod's extra desks ("interns"). Overflow goes to a second room. Agents walk along corridor aisles (`walk_route`) in from the door (Arriving), out (Leaving), or onto an occasional idle coffee-bar break, depth-sorted in 2.5D with desk rows.
- Character animation per state: idle, typing, reading, running (per-tool glowing monitor), thinking (dots), needs-you (raised hand + blinking lamp), queued (waiting on the lobby bench), error (red bubble), done (arms up). Priority-ordered overlay collision resolution keeps name badges (coloured by kind: Claude orange, sub amber, agy teal) and speech bubbles from overlapping.
- Ambient characters (not agents; `hit_test` returns `office:cat` / `office:ceo`, selectable and hoverable):
  - The CEO (you), `render/ceo.rs`: an executive corner office reserved by `layout.rs` at the top-right (pods never overlap it): dark parquet floor with a rug, wood-panelled back wall with a framed picture, a bookcase with coloured spines and a trophy, a glass partition with a side door, a high-back tufted leather chair, an executive desk (drawer pedestals, brass nameplate, monitor dashboard, lamp, papers, mug) and two visitor chairs in front of it (the boss-visit spot is the floor just left of them; the VOTE ballot area stays clear), plus a plant. Original sprite in a red-and-black vertical-stripe jersey (no crest, logo or sponsor), black shorts, optional number on the back. Mood mirrors the office: any NeedsYou means it stands, points toward the alert and shows a "!" bubble; agents working means it reviews papers and nods; all idle means coffee, leaning back, or looking out (back view with the number).
  - The office cat, `render/cat.rs`: ~12×8 px procedural pet whose behaviour is a pure function of `t_ms` (no RNG state). It walks between layout waypoints (sofa, windowsill, CEO desk, floor, desks) along cached floor aisles (a Manhattan route via `Layout::route`: hop down to the spot's aisle access point, walk the aisles, hop up), never across desks or the CEO nameplate, then sits, grooms and sleeps (zZ); it sometimes hops onto the desk of a NeedsYou/Error agent. The renderer keeps a small `cat::Memory` so an alert starting or clearing mid-walk never teleports it: the current walk finishes first, then it retargets. Drawn above furniture, below labels; its name shows only on hover/selection.
- Themes: `assets/themes/<name>/theme.toml` maps logical sprite names to (atlas file, x, y, w, h, frames), plus procedural `[colors]` (supporting `"checker"`, `"wood"`, `"plain"`, and architectural `"grid"` floors). Built-in presets include `procedural`, `modern`, `cozy`, `midnight`, `tokyo-night`, `nord`, `retro`, `retro-1bit` (green phosphor), `retro-amber`, `retro-gameboy`, and `cyberpunk`. Atlas paths resolve relative to the theme dir (absolute paths rejected, `..` may climb at most to `assets/`, e.g. `../../vendor/<pack>/<sheet>.png`). Window view: a theme may define `window_view` (foreground), `window_view_far` and `window_ground` sprites; the renderer draws them clipped inside each back-wall window's glass rect over a sky gradient, with a night tint and stars at night (`midnight`/`cyberpunk`/`tokyo-night` force night ambiance, and the static layer repaints when day/night or `lighting` flips). Overlays place status icons cleanly around nameplates (never covering agent tags) and suppress redundant label-echo or queued-chip-covered speech bubbles. Scanlines apply post-scale to keep 1px crispness without dimming pixel fonts. Themes are MIXABLE: config `theme = { floor = "cozy", furniture = "modern", characters = "retro" }`.

## TUI (crates/office/src/app/)
- Header adapts between full and compact `<105`-col layouts; the left area is the office and the right sidebar (toggle `s`, adaptive width `42`/`34` and height breakpoints) holds the agent table + Selected Agent Inspector strip, router gauge, and clickable alerts feed. When `theme_chrome` is on, header badges, active sidebar tabs, borders, and popup chrome match the active theme (`ui_palette`). Footer shows contextual key hints and renders transient toasts (so popups/toasts never fight Kitty graphics).
- Keys & mouse: `↑/↓`/`j k`/`g G` select agent, `Tab` jump to next NeedsYou/Error/active agent, `enter` or double-click scrollable details (`PgUp`/`PgDn`/`Ctrl-u`/`Ctrl-d`, visual context bar), click alert row to jump to its agent, click outside a modal to close it, `t` theme picker (all discovered presets + user themes with 4-colour swatches, live preview, enter keeps, esc reverts, 1-9 jump, "custom mix…" opens the mixer) / `[` `]` previous/next theme / `T` theme mixer, `z` toggle smooth `fill_viewport` scaling vs integer pixel-exact, `s` sidebar, `n` toggle notifications, `m` toggle audio chime, `c`/`C` clear/restore alerts, `r` hand-offs, `?` help, `q` quit.
- View menu (`v`): a scrollable popup of checkboxes (`[x]`/`[ ]`) for every display toggle, like a game's display settings. `↑↓`/`j k` move, `space`/`enter` toggle (applied live), `a` show all, `c` clean preset (`clean_on`: office elements + `selected_only_labels`, preserving `lighting`/`fill_viewport`/`scanlines`/`theme_chrome`), `h` hide overlays (names, bubbles, icons, nameplates, couriers off; zones, cat, CEO, and visual prefs stay), `esc`/`v`/`q` or a click outside closes and saves to the config file. The highlighted row shows a plain-language explanation (`VIEW_INFO` in ui.rs). `L` (outside the popup) toggles names and bubbles together (toast "name tags + bubbles on/off"; user-facing word is "name tags", not "labels"). The renderer takes the flags via `Renderer::set_show`; `zones`, `lighting`, `fill_viewport`, and `council_cabin` change the static layer/layout and are part of its cache keys, and with `council_cabin` off council members sit at ordinary desks (every agent keeps a seat).
- Control & Command Center actions: `Space` opens the `Command Center` quick-actions palette (`state::ACTIONS`); `a`/`d` approve/deny the selected agent's pending Claude permission (only when `office-hook --permission` is installed; otherwise disabled with a hint), and `A` opens `ConfirmApproveAll` to approve every pending permission at once; `x` safely stops any selected agent with a live PID after a y/n confirm (`kill_agent_pid` in `sources/control.rs` validates PIDs against a `/bin/ps` `comm`/`command` allowlist for `claude`/`agy`/`bun agy-route`/`node`, refusing init/self/parent and GUI helpers, sending `SIGTERM` then `SIGKILL` after 2.5 s); `K` (or clicking the sidebar `[K] Free RAM` strip) opens the `Free RAM` multi-select modal to stop idle/done agents or press `r` to reap orphan `agy` processes (`reap_orphan_agy`); `p` opens the `Dispatch` task launcher (`agy:worker`, `agy:architect`, `agy:supervisor`, `agy:tester`, `agy:fallback`, `agy:manager`, `agy:git`, `agy-cli`, `claude`, `claude-win`, `rosso-auto:council`, `rosso-auto:simple`); `f` opens a follow-up reply to the selected session (or report sender inside `ReportView`); `o` copies `cd <cwd> && claude --resume <id>` or `agy --resume <id>` via `pbcopy` and opens a Ghostty login-shell window; on the Jobs tab, `R` resumes the selected `rosso-auto` job and `X` opens `ConfirmAbortAuto` to abort it.
- Notifications: Critical alerts and NeedsYou use `osascript -e 'display notification …'` (rate-limited, toggled with `n`) and optional macOS audio chimes (`app/chime.rs`): `m` toggles `sound`, saves it to the config and plays a test chime when turning on. Chimes are independent of `n`: Glass = NeedsYou, Ping = boss inbox document, Basso = Critical alert or `⚠` escalation, rate-limited to one per 3 s (`Chimer`), spawned detached with `afplay` (`AfPlayer`, never blocks the UI). Decision logic is tested through the `Control::play_sound(Chime)` fake. Root cause of the old silence: sound defaulted to false, `m` was never persisted, and chimes only fired when a notification was also sent (so `n` off or the 10 s per-key notify cooldown muted them).
- Report reader (`app/reader.rs`): `parse_body` splits an agy router header (STATUS/ACCOUNT/MODEL/ROLE/.../RESPONSE:) from the content; `status_line` collapses it to one friendly line (✓/✗/?, role title, model, duration); `render_markdown` renders headings, bullets, numbered lists, bold, inline code, fences, tables and quotes, wrapped to the popup width minus a 2-column margin (max 96) so scroll limits are exact. Sections: Summary (first paragraph or 3 bullets, only for longer texts), What it was asked, What it sent back. The inbox card shows the status line plus the first summary line.
- Report reader v2: the popup is a header card (`reader::header_card`: verdict chip from `detect_verdict`, ROSSO doc-type chip, kind chip, title, `from → to` in agent kind colours, age, duration, model) over a `Tabs` row (Summary | Full | Brief | Raw, `App.reader_tab`, Tab/BackTab/←/→) over the scrolling body with a ratatui `Scrollbar`; the block title carries the `n/N` position. Summary = status line + first paragraph + `key_lists` (sections such as Findings / Required changes / Risks / Next steps, else a numbered run, else the first table) drawn as bullet cards with a severity colour (`severity_of`: critical/major/medium/minor words). `inline()` post-processes every run through `decorate` so `path/file.rs:123` is cyan and `http(s)://` URLs underlined. `y` copies the tab's plain text (`tab_plain`) and `w` saves `report_markdown` as `~/Downloads/rosso-report-<id>.md`; both go through new `Control::copy_text` / `save_file` hooks (real impls in `app/export.rs`: pbcopy on a thread, plain file write; fakes record in tests).
- Sidebar tabs (`app/panels.rs`, `App.side_tab`, keys 1-4, click on the bar): Agents (the original table + inspector + router + alerts), Jobs (`panels::jobs`: grouped by `Scene.report_jobs`, a report-id → job-name map filled by the reducer's `rosso_mail`, so no new fields on `Report`; stage = furthest of memo → task card → critique → decision → work order → sign-off → inspection by document type, shown with a `LineGauge`; attaches matching `AutoJob` entries and synthesizes auto-only rows via `office_core::auto_phase_progress`, rendering a compact `AUTO` status line with `flow`, `phase (step/total)`, `calls_used/max_calls`, `ruling` or `last_error`, and `[R]esume / [X]abort`), Activity (`panels::feed`: hand-offs with ✉ 📁 ⬆ ⚠ ✓ ✗ icons merged with `App.state_log`, the bounded log of NeedsYou/Error/Done/Queued transitions; Enter opens the report), Stats (router `Gauge`, `Sparkline`s from `App.samples` — one sample per 10 s in a 180-point ring buffer — per-session cost `BarChart`, alerts per level, token totals). Non-Agents tabs clear the agent-row hit caches. The header gets a right-aligned strip `● N active · ✉ N · $X · router b/c` when it fits.
- Help (`?`) is sectioned and scrollable (`help_lines`); the user guide is docs/GUIDE.md.

## Floors, council cabin and hand-offs
- Each top-level session gets its own floor zone (tinted patch + coloured border) with a nameplate strip on top showing the session name and member count; the agy lab is a neutral zone. Labels and bubbles are placed around nameplates and never cover them; only the selected agent's overlays are always shown.
- Council cabin: council members (`agy-council-*` relay subagents and `council-*` agy calls) sit in an aluminium-framed glass meeting room (door gap, light carpet tiles, wall screen with a tiny agenda, plant, "COUNCIL" sign) inside their session's zone instead of at desks. A long rectangular table (`procedural::council_table`, drawn in the dynamic pass) has two seats per long side: far-side members face us behind the table (it covers their lap, laptop lids toward us); near-side members are seen from behind in front of it (hair, chair back, lit laptop screen on the table). `Pod::cell` gives council pods their own rows (`COUNCIL_ROW0`/`COUNCIL_ROW_DY`), `layout::COUNCIL_TABLE` is the table rect, `Layout::seat_aisle` sends walkers to the cabin door, and routes (cat and walkers) step around the table.
- agy calls nest under the relay subagent that started them (`agy-<role>` subagent in the same project tree, oldest unpaired first), else under the session in that tree. Manager calls show their domain (`manager:frontend`).
- Hand-offs (`EventKind::Handoff`, `Scene.reports`, bounded at 300): a brief (Task) is recorded when a child agent appears; a subagent's report (its hand-back or last assistant text, read from `<session>/subagents/agent-<id>.jsonl`, with its first message as the brief and `.meta.json` description as the title) goes to its parent on SubagentStop; a finished agy call's audit line goes to its relay; a session's turn output (Stop, `last_assistant_message` or transcript tail) goes to the boss (Result).
- Visuals: a postman (navy uniform, cap, satchel) walks each brief (white envelope) or report (yellow folder) from the sender's desk to the recipient's (at least 2.8 s). On a Result the session walks to the boss's office with a blue folder, presents it, and walks back. When a session waits on AskUserQuestion / ExitPlanMode it walks to the boss carrying the plan and waits there; the CEO shows a VOTE ballot (approve ✓ / request changes ✗) until you answer.
- ROSSO: a source (`sources/rosso.rs`, every 2 s, `OFFICE_ROSSO_DIR` or `~/.claude/run/rosso`) tails each recent job's `logbook.jsonl` (deliveries) and `mailroom.jsonl` (escalations; refusals become warn alerts) from the end, never replaying history, and emits `EventKind::RossoMail` with the document text. The reducer resolves ROSSO titles to live agents (Chief of Staff = the most recently active top-level session; "<Seat>/<Head>/…" by agy label, else relay subagent role; otherwise a desk-less `rosso:<title>` id) and records one hand-off per recipient with the titles as labels (Memo/Work Order/Task Card = Task, else Report; to the CEO = Result from a session).
- Title labels: agy calls are labelled `<--as title or ROSSO title>·<model>` (e.g. `Security Seat·neon-high`, `Backend Head·hydrogen-medium`) with `· job <job>` in the activity; relay subagents show their ROSSO title. `role` is unchanged, so the council cabin and relay nesting still work (`office-core/rosso.rs` maps both ways).
- Escalations (mailroom `escalation`, or a CEO-bound document containing `NEEDS_USER_INPUT`) also send the Chief of Staff session to the boss with a Result, triggering the usual boss-trip visual.
- TUI: `r` lists hand-offs (the selected agent's, `a` for all); enter reads one in full (brief + report); the agent detail popup lists its hand-offs.
- Boss inbox: reports with `to == None` (session Results, ROSSO deliveries to the CEO, escalations titled `⚠…`) are the CEO's mail. `App.inbox_seen` is a watermark of the highest report id seen; the first `observe` sets it to the newest boss report so history never floods. Unread = boss reports above the watermark; the header shows a yellow `✉ N` badge. The newest unread report is drawn as a compact notification card (about 48x6, bottom-right of the office; its rect is passed as the occlusion rect so Kitty graphics don't bleed over it, and it is hidden while any popup is open). While it shows, `Enter` reads it (opens the reader, marks it seen) and `Esc` dismisses it (marks all seen); every other key works as usual. Each new boss report also fires one notification through the `n`-toggled notify path (key `inbox:<id>`). `i` opens the inbox: the Reports popup with `inbox: true` (boss-addressed only, newest first, unread rows bold with a `•`, header `inbox · N unread`). The reader (`Popup::ReportView`) adds `n`/`p` (next/previous in the current list), `g` (close and select the sender), `o` (copy the resume command for the sender's session, as the main `o`), `a`/`d` (approve/deny the sender's pending permission); these act on the sender without changing the current selection (except `g`), and toast if the sender has left the office. Opening any report marks it seen.
- Single instance: the newest office takes over the hook socket (pid in `office.pid`; older holders get SIGTERM, then SIGKILL after 1.5 s). An office whose terminal is gone (re-parented to launchd) exits.

## System-audit extras (guard, verdicts, failures, trays)
All of this lives in `Scene` side maps (no new fields on `Agent`, `Report` or `RouterStatus`, so existing struct literals keep compiling); every map is `#[serde(default)]`, bounded and pruned when its agent leaves.
- Security Desk (`sources/agy_guard.rs`): tails `agy-guard.log.jsonl` (`OFFICE_RUN_DIR` or `~/.claude/run`) from the end. A `deny` line becomes a Warn alert `guard_deny` ("Security Desk blocked <agent> <tool>: <reason>", never the command text) plus `EventKind::GuardDecision`; the reducer keeps `Scene.guard` (`GuardStats`: total, per-reason counts capped at 24 reasons, last deny time/agent/tool). Render (`render/extras.rs::draw_guard`): a dark-uniform guard with cap, badge and a SECURITY nameplate stands next to the door; for 6 s after a denial he waves and a red hand bubble shows.
- Verdicts: `sources/agy_router.rs::audit_events` turns an audit line's `verdict` into `EventKind::Verdict{id,verdict}` for the agent attributed by (role, cwd); `RossoMail` verdicts set the sender's verdict in the reducer. `Scene.verdicts` (agent id -> upper-case verdict). A chip follows the name tag (`extras::draw_chip`): APPROVE/PASS/SUPPORT green, CHANGES_REQUESTED/INSUFFICIENT/APPROVE_WITH_CONDITIONS/REVISE amber, FAIL/OBJECT red; FAIL, OBJECT and REVISE pulse. Council seats show it too.
- Failures: PROVIDER_ERROR, INTERRUPTED and BLOCKED now alert (`provider_error`, `interrupted`, `blocked`). When an audit line has `failureFile` (or an errorCode) the router source reads `~/.claude/run/failures/<run>.json` (bounded, only `outcome`, `TIMEOUT_DIAGNOSIS` and `idleS` are used) and emits `EventKind::Failure{id, FailureInfo{outcome, diagnosis, hint}}`. Diagnosis: explicit `TIMEOUT_DIAGNOSIS`, else a timeout with `idleS >= 90` is STALLED, other timeouts ACTIVE_TOO_BIG. Hints: "stalled: retry once", "too big: split the task", otherwise "failed: see the run log"; the hint is appended to the alert and shown for 60 s in a red bubble with the red error icon on the agent.
- `--status` extras: `RouterExtra` (`Scene.router_extra`, event `RouterExtra`): ORPHAN_AGY, RESERVED_MB, WOULD_START, ROLE_MODELS. A rising orphan count raises a Warn alert `orphan_agy` and blinks one red LED on the server rack; `resolve_model` resolves agy models in priority order: audit log `models` → live `ROLE_MODELS` (from `--status`, stripping `/<timeout>` suffixes) → static `config.agy_models`.
- Document icons: the reducer stores each ROSSO document's type in `Scene.report_types` (report id -> doc type, parallel to `report_jobs`). Couriers carry distinct art (`doc_kind_for`): Critique red folder, Rebuttal orange folder, Decision Record paper with a red stamp, Sign-off Sheet paper with a green check, Inspection Report clipboard; Work Order / Task Card / Memo keep the envelope, everything else the yellow folder.
- Council round (`office_core::rosso::council_round`): the latest job with Task Card / Critique / Rebuttal / Decision Record documents; four dots on the meeting-room wall screen (lit when that step exists, the current one underlined) plus a progress bar, with `AGENDA` wall-screen overlay protection keeping council bubbles clear of the screen.
- In-trays (`sources/rosso.rs::scan_in_trays`, every 5 s, jobs updated < 2 h, freshest job wins per slug): files in `<job>/desks/<slug>/received/` become `EventKind::InTray{slug,count}`; the reducer matches the slug (`rosso::slug(title)`) to a live agy/relay agent -> `Scene.in_trays`; a paper stack with the count sits on that agent's desk.
- Session tracking & entrypoints (`sources/sessions.rs`, every 3 s, `OFFICE_SESSIONS_DIR` or `~/.claude/sessions`): reads `{pid, sessionId, entrypoint, cwd}` for `cc:<sessionId>`, computes inclusive `self + descendants` RSS via `/bin/ps` (`rss_by_pid`), emits `Gone` cleanup when a tracked session PID exits, and tags the session floor nameplate with DESKTOP (`claude-desktop`) or CLI.
- FIFO lobby queue & repo-busy badge (`sources/agy_router.rs`): parses `~/.claude/run/queue/<ms>-<pid>` tickets, `agy-route.worker-*.lock`, and first-line PIDs via `parse_first_pid` (`read_slots` multi-line lock parsing) into `Scene.queue_tickets` (`QueueTicket { pos, since_ms, repo_busy }`); the lobby bench sorts queued agents by ticket age with `#N` / `#N BUSY` chips, and the TUI inspector and detail popup show `queue #N` (`queue #N (repo busy)` when locked on the same repo).
- Wave progress strip (`sources/rosso.rs::scan_waves`): scans `~/.claude/run/rosso/<job>/runs/<plan>.state.json` into `Scene.waves` (`WaveState` with done/relay/pending counts and `WaveCall` verdicts); shown as a header strip in the office render and as a 4th progress row (`wave <plan>: <done>✓ <relay>⟳ <pending>·` + verdicts) in the `2 Jobs` sidebar (including wave-only jobs).
- `DIRECT` / `RELAY` dispatch route tag (`office_core::rosso::dispatch_mode`, `Scene.dispatch_modes`): tags top-level sessions as `DIRECT`, `RELAY`, or `DIR+RLY` (`Hybrid`) from `rosso dispatch` / live relay and agy activity, rendered on the Chief of Staff's desk and in the TUI inspector and detail popup (`dispatch` row).
- `rosso-auto` integration: `~/.claude/run/rosso/<job>/auto.json` snapshots are folded into `Scene.auto_jobs` (`AutoJob`, `EventKind::AutoJobs`, bounded keeping running + newest). `office_core::rosso::{latest_auto_job, auto_phase_progress}` drive the back-wall `AUTO` progress pill in the office render and `JobRow` attachment/synthesis in the `2 Jobs` sidebar (with `[R]` resume via `resume_rosso_auto` and `[X]` abort via `abort_rosso_auto` + `ConfirmAbortAuto`); `Dispatch` adds `rosso-auto:council` and `rosso-auto:simple` targets.

## Alerts (office-core/alerts.rs)
loop (same tool + same summary 4× in a row), stuck (no events for 120 s while not Idle/Done/NeedsYou/Queued), tool failures in a row (3), needs_you (permission/AskUserQuestion), router tool_denied/timeout/busy/empty_response, and cost (fires again at each multiple of config.cost_alert_usd, default $50: 50, 100, 150…).

## Config (~/.config/agent-office/config.toml)
theme mix, `[cat] enabled/name/color (grey|orange|black|white|calico)`, `[ceo] enabled/name/number/skin/hair/hair_style (short|curly|long|bald)`, fps (default 12), notifications on/off, sound on/off (default false), cost_alert_usd, price table, the agy role→model map, permission_timeout_s (default 0 = off).
`[show]` (missing table = defaults; edited via the `v` menu): `names` (agent name badges), `bubbles` (activity speech bubbles), `icons` (thinking / needs-you / done icon bubbles), `nameplates` (session floor zone headers), `zones` (zone tint and border), `couriers` (postmen and hand-off documents), `boss_visits` (sessions walking to the CEO), `cat`, `ceo`, `council_cabin`, `ambient` (coffee steam, rack LEDs, kanban pins, idle strolls), `selected_only_labels` (default `false`; when `true`, names and bubbles show only for the selected or hovered agent and agents in NeedsYou/Error), `lighting` (default `true`; window shafts, monitor glow halos, and room depth shading), `fill_viewport` (default `false`; smooth viewport-fill scaling toggled live with `z`), `scanlines` (default `false`; subtle CRT scanlines), `theme_chrome` (default `true`; match TUI borders/tabs/accents to the active theme). `office config` prints the effective values.

## Non-goals
No network access, no telemetry, and nothing outside the user's machine. Original name and art: we use only free (CC0/CC-BY) assets with attribution in `assets/CREDITS.md`.
